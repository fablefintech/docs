All Fable API requests must include a valid API key as a Bearer token in the `Authorization` header. There are no cookie-based or session-based authentication mechanisms — every request is authenticated independently using the key. Keep your API keys secure and rotate them immediately if you suspect they have been compromised.

## Header Format

Include the following header in every API request, replacing `<your_api_key>` with the key issued to your account:

```
Authorization: Bearer <your_api_key>
```

A complete request header set looks like this:

```
Authorization: Bearer fbl_live_sk_1a2b3c4d5e6f7g8h9i0j
Content-Type: application/json
```

## Obtaining Credentials

**Sandbox credentials** are available to all registered developer accounts. Visit [fablefintech.com/contact](https://fablefintech.com/contact) to request access or speak with your account manager. Sandbox API keys are prefixed with `fbl_test_sk_`.

**Production credentials** are issued after your integration passes a compliance review and your business documentation has been approved by the Fable onboarding team. Production API keys are prefixed with `fbl_live_sk_`. Do not use sandbox keys in a production environment — they will be rejected by the production base URL.

## Authentication Error Codes

| HTTP Status | Description |
|-------------|-------------|
| `401 Unauthorized` | The `Authorization` header is missing, malformed, or the API key is invalid. Check that you are sending the correct key and that the `Bearer` prefix is present. |
| `403 Forbidden` | The API key is valid but does not have permission to perform the requested operation. This can occur if your key is scoped to specific resources or if your account lacks a required feature flag. |
| `429 Too Many Requests` | The API key has exceeded its rate limit. Wait for the duration specified in the `Retry-After` header before retrying. |

## Example Requests

The examples below show how to authenticate a request to retrieve a transaction across common HTTP clients.

<CodeGroup>

```bash curl
curl https://api-sandbox.fablefintech.com/v1/transactions/txn_01HZ9QKBNK3J2F4P8GRWSV7MEX \
  -H "Authorization: Bearer fbl_test_sk_1a2b3c4d5e6f7g8h9i0j" \
  -H "Content-Type: application/json"
```

```javascript JavaScript
const response = await fetch(
  'https://api-sandbox.fablefintech.com/v1/transactions/txn_01HZ9QKBNK3J2F4P8GRWSV7MEX',
  {
    method: 'GET',
    headers: {
      'Authorization': 'Bearer fbl_test_sk_1a2b3c4d5e6f7g8h9i0j',
      'Content-Type': 'application/json',
    },
  }
);

const data = await response.json();
console.log(data);
```

```python Python
import requests

headers = {
    "Authorization": "Bearer fbl_test_sk_1a2b3c4d5e6f7g8h9i0j",
    "Content-Type": "application/json",
}

response = requests.get(
    "https://api-sandbox.fablefintech.com/v1/transactions/txn_01HZ9QKBNK3J2F4P8GRWSV7MEX",
    headers=headers,
)

print(response.json())
```

</CodeGroup>

<Warning>
  Never expose your API key in client-side code, public repositories, or any environment where it can be read by unauthorized parties. API keys grant full access to your Fable account. Use environment variables or a secrets manager to inject keys at runtime, and ensure they are excluded from version control via `.gitignore` or equivalent.
</Warning>
