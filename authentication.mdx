Every request to the Fable Fintech API must be authenticated using an API key passed as a Bearer token in the `Authorization` header. This applies to all endpoints across all products — DigiRemit, BizPay, DigiBureau, Ex-Core, and the rest of the platform. There are no public or unauthenticated endpoints. This document explains how to obtain your credentials, how to include them correctly in your requests, and how to handle authentication failures.

## Obtaining Your API Key

Fable Fintech issues separate credentials for sandbox and production environments. The two sets of keys are completely isolated — sandbox keys will not work against the production API, and vice versa.

**Sandbox credentials** are provisioned when you request access at [fablefintech.com/contact](https://fablefintech.com/contact). Once the Fable team creates your sandbox organization, your API key will be delivered to you directly. Sandbox keys are scoped to simulated environments and carry no financial risk.

**Production credentials** are issued after your organization completes a compliance review and receives go-live approval from Fable. This process includes verification of your regulatory status, AML/KYC framework, and integration testing sign-off. Contact your Fable account manager to initiate the production onboarding process.

## Making Authenticated Requests

Include your API key in every request using the standard HTTP `Authorization` header with the `Bearer` scheme:

```
Authorization: Bearer <your_api_key>
```

The following examples show how to make an authenticated request to retrieve your transaction list across common HTTP clients.

<CodeGroup>

```bash curl
curl -X GET "https://api-sandbox.fablefintech.com/v1/transactions" \
  -H "Authorization: Bearer $FABLE_API_KEY" \
  -H "Content-Type: application/json"
```

```javascript JavaScript
const response = await fetch(
  "https://api-sandbox.fablefintech.com/v1/transactions",
  {
    method: "GET",
    headers: {
      Authorization: `Bearer ${process.env.FABLE_API_KEY}`,
      "Content-Type": "application/json",
    },
  }
);

const data = await response.json();
console.log(data);
```

```python Python
import requests
import os

url = "https://api-sandbox.fablefintech.com/v1/transactions"

headers = {
    "Authorization": f"Bearer {os.environ['FABLE_API_KEY']}",
    "Content-Type": "application/json",
}

response = requests.get(url, headers=headers)
data = response.json()
print(data)
```

</CodeGroup>

## Base URLs

Fable Fintech maintains separate base URLs for sandbox and production traffic. Ensure you are targeting the correct environment for your use case.

<Note>
  **Sandbox:** `https://api-sandbox.fablefintech.com/v1`
  Use this URL during development and integration testing. All transactions are simulated and no real funds are moved.
</Note>

<Note>
  **Production:** `https://api.fablefintech.com/v1`
  Use this URL only after your organization has received go-live approval from Fable. All transactions are live and processed on real payment networks.
</Note>

## Authentication Errors

When a request fails due to an authentication or authorization issue, the API returns one of the following HTTP status codes. Review the table below to understand what each error means and how to resolve it.

| Status Code | Name | Description |
|---|---|---|
| `401` | Unauthorized | The `Authorization` header is missing, malformed, or contains an invalid API key. Verify that your key is correct and that the header is formatted as `Bearer <your_api_key>`. |
| `403` | Forbidden | The API key is valid, but it does not have permission to access the requested resource. This typically means the endpoint is not enabled for your account or environment. Contact Fable support to review your key's scope. |
| `429` | Too Many Requests | You have exceeded the rate limit for your API key. Slow down your request rate and implement exponential backoff before retrying. Rate limit thresholds are communicated during onboarding. |

## Best Practices

Following these practices will keep your integration secure and minimize the risk of credential exposure.

<Tip>
  **Never expose API keys in client-side code.** API keys must be used exclusively in server-side or backend environments. Embedding a key in a browser-side JavaScript bundle, a mobile app binary, or a public repository gives anyone who finds it full access to your account.
</Tip>

<Tip>
  **Store keys in environment variables.** Rather than hard-coding your API key in source files, read it from an environment variable at runtime (e.g. `process.env.FABLE_API_KEY` or `os.environ['FABLE_API_KEY']`). This keeps secrets out of your codebase entirely.
</Tip>

<Tip>
  **Rotate keys periodically.** Even if a key has not been compromised, rotating it on a regular schedule (e.g. every 90 days) limits the blast radius if it ever is. Contact your Fable account manager or use the credentials portal to issue a replacement key and deprecate the old one.
</Tip>

<Warning>
  **Production API keys must be treated as highly sensitive secrets.** Never commit them to source control — even in private repositories. Use a secrets manager (such as AWS Secrets Manager, HashiCorp Vault, or GitHub Actions encrypted secrets) to store and inject production credentials into your runtime environment. A compromised production key could expose your customers' financial data and allow unauthorized transactions to be initiated on your behalf.
</Warning>
