This guide walks you through a complete outward remittance flow using DigiRemit — the most common Fable integration use case. You will fetch a live exchange rate, verify the sender's identity, create a transaction, and track it through to delivery. Each step maps to a specific API call, and the guide includes working code examples you can adapt directly into your integration.

<Steps>
  <Step title="Fetch the Exchange Rate">
    Before creating a transaction, fetch the current exchange rate for your corridor. The `rate_id` returned here must be included when you create the transaction to lock the rate.

    ```bash
    curl --request GET \
      --url "https://api-sandbox.fablefintech.com/v1/fx/rates?from=USD&to=INR" \
      --header "Authorization: Bearer <your_api_key>"
    ```

    **Response:**

    ```json
    {
      "rate_id": "RATE-20240115-XYZ789",
      "from_currency": "USD",
      "to_currency": "INR",
      "rate": 83.42,
      "valid_until": "2024-01-15T10:15:00Z",
      "margin_included": true
    }
    ```

    Store the `rate_id` and check `valid_until` — rates are typically valid for 30 seconds. If the rate expires before you create the transaction, fetch a fresh one.
  </Step>

  <Step title="Verify the Sender (KYC)">
    You must verify the sender's identity before initiating a transaction. Call `POST /compliance/kyc` with the sender's identity details. If your platform has already completed KYC for this customer, you can skip this step and reference their existing `customer_id`.

    ```bash
    curl --request POST \
      --url "https://api-sandbox.fablefintech.com/v1/compliance/kyc" \
      --header "Authorization: Bearer <your_api_key>" \
      --header "Content-Type: application/json" \
      --data '{
        "customer_id": "CUST-001",
        "full_name": "Jane Doe",
        "date_of_birth": "1990-04-15",
        "id_type": "PASSPORT",
        "id_number": "X12345678",
        "nationality": "US"
      }'
    ```

    A successful response returns a `kyc_status` of `APPROVED`. If the status is `PENDING`, the verification is still in progress — you can proceed once a `compliance.kyc_completed` webhook event is received.
  </Step>

  <Step title="Create the Transaction">
    With a valid `rate_id` and a KYC-approved sender, create the remittance transaction by calling `POST /transactions`. Include full sender and receiver details, the amount, corridor, delivery channel, and the locked rate.

    ```bash
    curl --request POST \
      --url "https://api-sandbox.fablefintech.com/v1/transactions" \
      --header "Authorization: Bearer <your_api_key>" \
      --header "Content-Type: application/json" \
      --data '{
        "sender": {
          "customer_id": "CUST-001",
          "full_name": "Jane Doe",
          "country": "US"
        },
        "receiver": {
          "full_name": "Ravi Kumar",
          "account_number": "9876543210",
          "bank_code": "SBIN0001234",
          "country": "IN"
        },
        "amount": 500.00,
        "source_currency": "USD",
        "destination_currency": "INR",
        "corridor": "US-IN",
        "channel": "BANK_TRANSFER",
        "rate_id": "RATE-20240115-XYZ789",
        "reference": "REF-2024-00123",
        "purpose": "FAMILY_SUPPORT"
      }'
    ```
  </Step>

  <Step title="Handle the Response">
    A successful `POST /transactions` call returns a `201 Created` response with the transaction record. Extract and store the `transaction_id` — you will need it to track status and handle any exceptions.

    ```json
    {
      "transaction_id": "TXN-20240115-ABC123",
      "status": "PENDING",
      "amount": 500.00,
      "source_currency": "USD",
      "destination_amount": 41710.00,
      "destination_currency": "INR",
      "rate": 83.42,
      "corridor": "US-IN",
      "channel": "BANK_TRANSFER",
      "created_at": "2024-01-15T10:00:00Z",
      "estimated_delivery": "2024-01-15T14:00:00Z"
    }
    ```

    Display the `transaction_id`, destination amount, locked rate, and `estimated_delivery` time to your end user as confirmation of the transaction.
  </Step>

  <Step title="Track Transaction Status">
    Poll `GET /transactions/{id}/status` to track the transaction through its lifecycle, or use webhooks (recommended) to receive push notifications at each status change.

    ```bash
    curl --request GET \
      --url "https://api-sandbox.fablefintech.com/v1/transactions/TXN-20240115-ABC123/status" \
      --header "Authorization: Bearer <your_api_key>"
    ```

    **Response:**

    ```json
    {
      "transaction_id": "TXN-20240115-ABC123",
      "status": "IN_TRANSIT",
      "updated_at": "2024-01-15T11:30:00Z"
    }
    ```

    A transaction passes through the following statuses in the normal flow:

    | Status | Description |
    |---|---|
    | `PENDING` | Transaction received and queued |
    | `SCREENING` | AML and sanctions checks in progress |
    | `PROCESSING` | Compliance cleared; payment being processed |
    | `IN_TRANSIT` | Funds dispatched to the destination bank or channel |
    | `DELIVERED` | Funds confirmed delivered to the recipient |
  </Step>

  <Step title="Handle Exceptions">
    Not all transactions reach `DELIVERED`. Your integration must handle `FAILED` and `CANCELLED` statuses gracefully.

    ```bash
    curl --request GET \
      --url "https://api-sandbox.fablefintech.com/v1/transactions/TXN-20240115-ABC123/status" \
      --header "Authorization: Bearer <your_api_key>"
    ```

    **Failed transaction response:**

    ```json
    {
      "transaction_id": "TXN-20240115-ABC123",
      "status": "FAILED",
      "failure_reason": "COMPLIANCE_REJECTION",
      "failure_code": "AML_ALERT",
      "updated_at": "2024-01-15T10:45:00Z"
    }
    ```

    **Retry guidance:**

    - `COMPLIANCE_REJECTION` — Do not automatically retry. Review the `failure_code` and contact your compliance team.
    - `INVALID_ACCOUNT` — Correct the receiver account details and create a new transaction.
    - `RATE_EXPIRED` — Fetch a fresh rate and re-submit with the new `rate_id`.
    - `NETWORK_ERROR` — Safe to retry after a short delay using exponential backoff.

    To cancel a transaction that is still in `PENDING` status, call `DELETE /transactions/{id}`.
  </Step>
</Steps>

## Code Examples

<CodeGroup>

```javascript JavaScript
const axios = require('axios');

const BASE_URL = 'https://api-sandbox.fablefintech.com/v1';
const API_KEY = process.env.FABLE_API_KEY;

const headers = {
  Authorization: `Bearer ${API_KEY}`,
  'Content-Type': 'application/json',
};

async function createRemittance() {
  // Step 1: Fetch FX rate
  const rateResponse = await axios.get(`${BASE_URL}/fx/rates?from=USD&to=INR`, { headers });
  const { rate_id } = rateResponse.data;

  // Step 2: Create transaction
  const txnResponse = await axios.post(
    `${BASE_URL}/transactions`,
    {
      sender: { customer_id: 'CUST-001', full_name: 'Jane Doe', country: 'US' },
      receiver: {
        full_name: 'Ravi Kumar',
        account_number: '9876543210',
        bank_code: 'SBIN0001234',
        country: 'IN',
      },
      amount: 500.00,
      source_currency: 'USD',
      destination_currency: 'INR',
      corridor: 'US-IN',
      channel: 'BANK_TRANSFER',
      rate_id,
      reference: 'REF-2024-00123',
      purpose: 'FAMILY_SUPPORT',
    },
    { headers }
  );

  const { transaction_id, status } = txnResponse.data;
  console.log(`Transaction created: ${transaction_id} — Status: ${status}`);
  return transaction_id;
}

async function pollStatus(transactionId) {
  const response = await axios.get(
    `${BASE_URL}/transactions/${transactionId}/status`,
    { headers }
  );
  return response.data.status;
}

createRemittance().then(pollStatus).then(console.log);
```

```python Python
import os
import requests

BASE_URL = "https://api-sandbox.fablefintech.com/v1"
API_KEY = os.environ["FABLE_API_KEY"]

headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json",
}

def create_remittance():
    # Step 1: Fetch FX rate
    rate_resp = requests.get(f"{BASE_URL}/fx/rates?from=USD&to=INR", headers=headers)
    rate_resp.raise_for_status()
    rate_id = rate_resp.json()["rate_id"]

    # Step 2: Create transaction
    payload = {
        "sender": {"customer_id": "CUST-001", "full_name": "Jane Doe", "country": "US"},
        "receiver": {
            "full_name": "Ravi Kumar",
            "account_number": "9876543210",
            "bank_code": "SBIN0001234",
            "country": "IN",
        },
        "amount": 500.00,
        "source_currency": "USD",
        "destination_currency": "INR",
        "corridor": "US-IN",
        "channel": "BANK_TRANSFER",
        "rate_id": rate_id,
        "reference": "REF-2024-00123",
        "purpose": "FAMILY_SUPPORT",
    }

    txn_resp = requests.post(f"{BASE_URL}/transactions", json=payload, headers=headers)
    txn_resp.raise_for_status()
    txn = txn_resp.json()

    print(f"Transaction created: {txn['transaction_id']} — Status: {txn['status']}")
    return txn["transaction_id"]

def poll_status(transaction_id):
    resp = requests.get(
        f"{BASE_URL}/transactions/{transaction_id}/status", headers=headers
    )
    resp.raise_for_status()
    return resp.json()["status"]

transaction_id = create_remittance()
print(poll_status(transaction_id))
```

</CodeGroup>

<Tip>
  Use [webhooks](/guides/webhooks) instead of polling `GET /transactions/{id}/status` in production. Webhooks deliver real-time status updates to your server without the overhead of repeated API calls, and they eliminate the risk of missing a status transition between poll intervals.
</Tip>
